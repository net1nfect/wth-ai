## Limitations

Berikut adalah gap signifikan yang **mencegah assessment ini menjadi submission-ready:**

### 1. ❌ Tidak Ada Test Accounts
```
test_accounts: []
```
Tanpa dua akun test (misal: `userA` dan `userB` dengan role berbeda), pengujian berikut **tidak dapat dilakukan secara valid:**
- IDOR / BOLA pada resource endpoint
- Privilege escalation antar role (mahasiswa → dosen → admin)
- Session isolation / token leakage antar akun

**Aksi yang dibutuhkan:** Minta tim SEVIMA menyediakan minimal:
```
userA: mahasiswa_test@universitas-a.ac.id / [password]
userB: dosen_test@universitas-a.ac.id    / [password]
userC: admin_test@universitas-a.ac.id    / [password]  ← opsional
```

### 2. ❌ Tidak Ada Evidence / Transcript
```
findings:    []
hypotheses:  []
methodology: []
```
Sesuai **Evidence Law (TTST)**, tidak ada klaim vulnerability yang dapat diverifikasi. Semua temuan tanpa referensi `[TX:...]` atau `[EV:...]` diklasifikasikan sebagai **HIPOTESIS (belum dibuktikan)**.

### 3. ⚠️ Environment Production
Target adalah environment **production**. Rate limit 2.0 rps sudah dikonfigurasi, namun tanpa methodology yang terdokumentasi, tidak dapat dikonfirmasi apakah pengujian dilakukan dengan aman.

### 4. ⚠️ Wildcard Scope Luas
```

```
Scope wildcard mencakup semua subdomain platform SEVIMA. Tanpa Asset Graph yang terdokumentasi, ada risiko pengujian menyentuh tenant universitas lain yang mungkin bukan target yang dimaksud.
